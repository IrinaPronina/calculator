## 1. Продуктовая рамка (определено 2026-09-08)

**Калькулятор — НЕ продукт на продажу.** Задача — продавать материалы (ассортимент
ООО «ПРОФОСНОВА»: топпинги, пропитки, герметики, фибра, фиксаторы, ВПС-полотно,
плёнка). Калькулятор бесплатный инструмент для небольших подрядчиков по промышленным
полам; окупается маржой с материалов, а не подпиской.

**Аудитория:** небольшие подрядчики по бетонным полам. Считают в Excel, у каждого свои
цены и свой прайс на работы. Боль: посчитать быстро, не уйти в минус, выдать заказчику
приличное КП.

**Что из этого следует:**

- Биллинг, тарифы, подписки НЕ нужны. Метрика успеха — не MRR, а: расчёты → заявки →
  тонны отгруженного материала.
- Расчёт делится надвое: НАША номенклатура (цена и наличие от ПРОФОСНОВЫ) и ВСЁ
  ОСТАЛЬНОЕ (бетон, арматура, сетка — цены подрядчика, мы их не трогаем). Механизм
  персональных настроек own/global под это уже есть и спроектирован правильно.
- КП делает подрядчик для СВОЕГО заказчика → белый лейбл, его логотип, его маржа.
  Наша выгода — спецификация материалов внутри расчёта + кнопка «заказать».
- Приватность как требование и как аргумент продаж: подрядчик не должен бояться, что
  поставщик видит его объекты и маржу. Его цены на работы не видит никто.
- Ограничение сбыта: дилерство в трёх областях. Калькулятор считает объекты по всей
  стране, отгружать можем только в свои области — это влияет на воронку заявок.

### Ветка 1: наличие и заявка

Из 1С тянем ОСТАТКИ, а не цены (разворот — в разделе 3). Покрытие «11 из 35» оказалось
не провалом: отсутствующие бетон/сетка/арматура — это то, чем ПРОФОСНОВА не торгует;
найденные 11 — ровно её ассортимент. Отпускная цена ведётся руками в админке как
global-шаблон (в 1С её нет), закупочная из 41 счёта подрядчику не показывается никогда.

### Ветка 2: выбор СИСТЕМЫ материалов

Подрядчик выбирает систему (MONOPOL / MUREXIN / BAU Schild / МОНОХИМ — все есть в
номенклатуре) → пересчитываются другие материалы и другие расходы. Даёт сравнение
«этот пол в системе A стоит X ₽/м², в системе B — Y», причём обе системы на складе.
Прямой инструмент продажи материалов.

**Требует рефакторинга домена `app/domain/concrete-calc.ts` (1136 строк).** Сейчас:

- материал адресуется жёстким кодом (`case '1221'`), а должен адресоваться РОЛЬЮ
  (упрочнитель / пропитка / герметик / фибра / разделительный слой / демпфер);
- названия материалов продублированы в домене
  (`'1221': { name: 'Топпинг MONOPOL Top 200 корундовый', unit: 'кг', note: 'расход 3-5 кг/м²' }`);
- расходы размазаны по трём местам: `FormulaSettings` (sealerConsumptionLpm2), поля
  запроса (toppingAmount) и литералы в коде (кратность мешка 25 кг зашита числом в
  `Math.ceil((toppingAmount*area)/25)*25` — у другой системы фасовка другая).

Целевая модель: `system = { id, name, brand, items: [{ role, materialId, consumption, packSize }] }`.
Расчёт спрашивает роль — система отдаёт номенклатуру, расход и фасовку.
`FormulaSettings` расщепляется: геометрия (шаг реза, нахлёсты) остаётся общей, расходы
материалов уезжают в систему.

Порядок: 1) вынести роли и расходы, MONOPOL становится дефолтной системой — поведение
не меняется, это чистый рефакторинг; 2) добавить вторую систему. Страховка есть:
`npm run test:calculate-regression` с baseline в `scripts/calculate-regression-baseline.json`.

### Открытый вопрос

Что делать первым — дешёвую ветку 1 (наличие + заявка + белый лейбл), чтобы быстрее
получить живых пользователей и обратную связь, или ветку 2 (рефакторинг под системы),
которая всё равно неизбежна.

## 3. Интеграция с 1С: цены и остатки (обсуждено 2026-09-07/08)

### Что за 1С

- Конфигурация «Элит-строительство» — отраслевое решение на базе 1С:Бухгалтерии,
  ТЕКУЩАЯ рабочая база. Организация: ООО «ПРОФОСНОВА».
- Платформа 8.3.27.1936 — свежая: с Let's Encrypt работает, JSON и HTTPСоединение из
  коробки, автоматизация технически возможна.
- База локальная, наружу не смотрит, белого IP нет → только push из 1С либо ручная
  загрузка файла.
- Документов «Установка цен номенклатуры» НЕТ → прайса в 1С не существует. Обороты по
  счёту 42 пустые → учёт по покупным ценам.
- ОСНО → суммы на счетах учёта без НДС. Материалы на счёте 41 «Товары», не на 10.
- Источник цены: ОСВ по счёту 41, цена = оборот Дт (сумма) / оборот Дт (количество).

### Разбор первой выгрузки (ОСВ по 41 за 01.01–08.09.2026, 265 позиций)

**Главная проблема — покрытие.** Из 35 материалов калькулятора в 1С нашлось ~11.
Отсутствуют полностью: бетон (4 позиции), сетка сварная (9), арматура (7), труба
профильная, мембрана профилированная — то есть ровно то, что даёт основную сумму сметы.
На 41 счёте лежит ассортимент, которым фирма торгует: затирочные машины и запчасти,
диски, гладилки, топпинги, пропитки, герметики, фиксаторы. Бетон и металл через 41 не
проходят.

**Цены в калькуляторе выше закупочных на 19–76%**: ВПС-полотно ×1.25, фибра Macro ×1.76,
микрофибра ×1.59, топпинг Top 200 ×1.63, Sealer 2 ×1.58, герметик PU 40 ×1.42,
стульчик 25мм ×2.42, ФС-25/30 ×1.19, змейка ×1.25. Разброс не константа → это не НДС и
не единый коэффициент. Значит `price` в settings — не закупочная цена, и импорт «в лоб»
обрушит сметы. НЕ РЕШЕНО: что такое `price` — закупка или уже с наценкой. В расчёте
(`calcPriceWithIncrease`) итог = price + price*increase/100, у материалов increase 2–10%.

**Плёнка — разные единицы:** в калькуляторе за метр (11 и 18), в 1С за рулон (1446 и
2881). Подтверждает необходимость `factor`.

**Один-ко-многим подтвердился:** «Фиксатор металлический „змейка" ф4» — одна строка
калькулятора, в 1С 8 позиций по высоте (40/50/60/70/80/100/110/130мм).

**В выгрузке нет** кода, артикула и единицы измерения — только наименование. Лечится: в
настройках отчёта вкладка «Дополнительные поля» → добавить Код, Артикул, Единица
измерения. Перевыгрузить.

**Формат файла:** 1С отдаёт настоящий BIFF8 .xls; на позицию ДВЕ строки — «БУ» (суммы) и
«Кол.» (количество), имя в объединённой ячейке на обе строки. Парсер должен идти парами
строк, а не по одной.

### Принятые решения

- Первая версия импорта — СПРАВКА, А НЕ АВТОЗАМЕНА: в `/edit` рядом с ценой показывать
  «в 1С закупка X от такой-то даты, расхождение Y%», решение принимает человек.
  Автоподстановку включать только после того, как решён вопрос про смысл `price`.
- `priceMap` — соответствие ОДИН-КО-МНОГИМ:
  `{ calcId, kind, refs1c: [...], factor, aggregation: 'last'|'avg'|'min' }`.
- `factor` — ТОЛЬКО пересчёт единиц. Пересчёт НДС — отдельный флаг режима импорта.
  Не смешивать.
- `priceFeed` — сырые снимки как есть, для аудита и переигрывания маппинга.
- `stock` — остатки отдельно от цен, только для отображения, в расчёт не входят.
- Цены пишем только в глобальный шаблон `settings` (scope:'global'), version++, только
  числовые поля. Личные `user.settings` не перезаписываем.
- Поле `id` в settings (`7053`, `0101`) — внутренние коды калькулятора, НЕ коды 1С.
- Работы (pay) из 1С не вытянуть: в бухгалтерии они на 20/26 без номенклатурной
  детализации. Остаются ручными.

### Открытые вопросы

- Где живут бетон, сетка, арматура, мембрана — другой счёт (10, 20), другая фирма,
  другая база? Проверить ОСВ по 10 и по 20.
- `price` в калькуляторе — закупка или отпускная? От ответа зависит, автозамена это или
  подсказка.
- Опыта работы с 1С нет; интерфейс базы непривычный (пункта «Справка» в меню не нашлось,
  версию нашла в другом месте).

## 4. Деплой и эксплуатация (задеплоено 2026-07-17)

Подробная пошаговая инструкция — в `DEPLOY.md` в корне проекта. Здесь — контекст и
то, чего в ней нет.

**Что где:** VPS Timeweb Cloud, IP `72.56.248.211`, Ubuntu 26.04, hostname `ubuntu-calc`,
код в `/opt/calculator`. Домен https://calcapp.webtm.ru — бесплатный техдомен Timeweb
Cloud (создан 2026-07-17 в панели «Домены и SSL», A-запись автоматом; DNS техдомена не
редактируется). HTTPS — Let's Encrypt через `certbot --nginx`, автопродление systemd-таймером.

**Схема:** docker compose (app + mongo:7 как single-node replica set `rs0` — обязателен
для транзакций better-auth). Приложение слушает только `127.0.0.1:3000`, наружу отдаёт
nginx (80/443, редирект на https). ufw: 22/80/443. SSH только по ключу. Docker Hub через
зеркало `dockerhub.timeweb.cloud` (в `/etc/docker/daemon.json`) — иначе 429 с российских IP.

**Обновление:** rsync с мака (без `node_modules/.next/.env/.git`) →
`docker compose up -d --build`. Миграции с хоста:
`DB_URL='mongodb://localhost:27017/?directConnection=true' DB_NAME=calculator npx migrate-mongo up`
(`directConnection` обязателен из-за replica set).

**Правила безопасности данных:** НИКОГДА не запускать `docker compose down -v` — флаг
`-v` удаляет базу. Данные живут в volume `calculator_mongo-data`, пересборок не боятся.

**История и долги по безопасности:**

- Первый сервер был скомпрометирован (майнер + подмена порта 3000 редиректом на
  booter-сайт) из-за root-пароля и открытого 3000 — переустановлен с нуля.
- Старый Atlas-кластер больше не используется.
- ⚠️ Пароль Atlas и пароль seed-миграции утекли в git-историю проекта. Значения в
  истории коммитов; их надо считать скомпрометированными и ротировать, историю — чистить.
- Сброс пароля пользователя: `scripts/reset-password.mjs`.
- `BETTER_AUTH_URL=https://calcapp.webtm.ru` (в `.env` на сервере).
